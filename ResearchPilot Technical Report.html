01Summary

ResearchPilot answers questions across a set of uploaded PDFs. Instead of searching once, it plans focused queries, retrieves passages, asks a model whether the evidence actually covers the question, and searches again for the missing parts within a fixed budget. The final answer may only cite passages the system retrieved, and code rejects any citation that does not map to one.

The full MVP from the design guide is implemented: ingestion with page-level metadata, dense and hybrid retrieval with optional reranking, a bounded LangGraph agent, programmatic citation checks, abstention when evidence is missing, prompt-injection defences, a FastAPI service with streaming progress, a Streamlit interface with a source PDF viewer, LangSmith tracing, and an evaluation harness that compares six system variants.

It runs entirely on a laptop with a local open model (qwen3.5:4b through Ollama), with no paid API required. The comparative evaluation has been built but not yet run on a question set, so this report claims no accuracy numbers. Section 13 lists what was measured during development; section 14 describes the evaluation that will produce the headline results.

02The problem

People reviewing research papers often ask questions that span documents: compare two methods, explain a trade-off, find where a claim is supported. A basic retrieval-augmented generation (RAG) pipeline embeds the question once, takes the top few passages, and asks a model to answer. When the evidence is spread across papers or phrased in different terms, that single search misses part of it, and the model still produces a confident answer.

ResearchPilot targets three failures of that baseline:

  • Incomplete evidence. One query cannot cover a multi-part question. The agent decomposes the question and searches again for what is missing.
  • Untraceable claims. Answers must cite a filename and page, and those citations are checked in code rather than trusted.
  • False confidence. When the documents do not contain the answer, the system says so instead of filling the gap from the model's general knowledge.

04Ingestion

Uploads are treated as untrusted input. Each file is checked for a .pdf name, a real %PDF- header and a size limit before any parsing. Text is extracted page by page so every chunk knows its page, and page numbers are converted to 1-based values once, at the source, so citations always match what a reader sees.

Cleaning

  • Running headers and footers are detected as lines that repeat at the top or bottom of at least half the pages, after normalising digits so that "Page 3" and "Page 4" match.
  • The reference list is cut when a "References" or "Bibliography" heading appears in the second half of the document. Reference lists cause false keyword matches.
  • Hyphenated line breaks are rejoined and whitespace is normalised.

Identity and idempotency

The document_id is the first 16 hex characters of the file's SHA-256 hash, and each chunk_id is derived from the document, page and chunk index. Uploading the same bytes twice therefore produces the same IDs and is detected as a duplicate, which keeps the index clean and makes evaluation runs reproducible.

05Retrieval

Retrieval is built as switches so that each improvement can be measured on its own. The design rule from the project guide is to add one change at a time; if hybrid search, reranking and the agent loop were introduced together, no result could be attributed to any of them.

StageMethodWhy
DenseCosine search over MiniLM embeddings, top-k = 5Matches meaning across different wording
HybridBM25 over the same chunks, fused with reciprocal rank fusion (k = 60)Technical text depends on exact names and acronyms
Per-documentTop-k inside each document for comparison questionsOne long paper cannot crowd out the others
RerankCross-encoder over about 20 candidates, keep 5Better ordering of the passages the model sees
DeduplicateBy chunk_id, keeping the best scoreSeveral queries often return the same chunk
PackageLabel each kept chunk S1, S2, … with file and pageGives the model a closed set of citable sources

The keyword index is built in process from the stored chunks and rebuilt whenever the store changes, which a version counter on the store signals. This is simple to reason about and adequate for a personal library of hundreds of papers; section 15 notes where it stops scaling.

06The agent loop

The agent is a LangGraph state machine with five steps. The only loop goes through refine, and the router checks the round counter before every refine, so the number of retrieval rounds cannot exceed MAX_ROUNDS. LangGraph's recursion limit is set as a second guard.

StepDoesOn bad model output
planWrites up to 3 focused queries; flags comparison questions, which switches retrieval to per-documentFalls back to the raw question
retrieveRuns every query, merges with earlier evidence, keeps passages the evaluator marked relevant when over the context budgetNot an LLM step
evaluateReturns {sufficient, missing_information, relevant_source_ids, confidence}, validated by PydanticCounted as insufficient, never as success
refineWrites new queries aimed at the listed gaps and filters out queries already triedSearches for the missing facts directly
answerWrites a structured answer from labelled evidence onlyOne retry, then a clear failure message

Empty retrieval skips the evaluator and the answer model entirely and returns a fixed statement that the indexed documents do not contain enough evidence. Planning, evaluation and refinement can run on a cheaper model than the final answer through a separate setting.

07Citations and abstention

The model receives each passage with a label such as [S3] and must return JSON containing the answer text and a list of claims, each with the labels that support it. Code then enforces the rules:

  • Every cited label must exist in the retrieved set. Unknown labels trigger one regeneration with a correction message; if they persist, they are stripped from the text and the claims.
  • Filenames and page numbers in the response come from stored metadata. Text the model writes about files or pages is never used.
  • An answer with no valid citation is marked as unverified in the response.
  • When the model cites only through the claims list, the claims and their sources are appended to the answer so every statement stays traceable.
What this guaranteesA test can assert that no response ever cites a passage that was not retrieved. It does not guarantee that a cited passage truly supports its claim; that needs the claim-verification step and the citation-correctness metric planned in sections 14 and 16.

08Security

Document text is untrusted. A PDF can contain instructions aimed at the model, so the system limits what such text can reach.

  • Document text appears only in the user message, inside <evidence> tags, never in the system prompt. Any </evidence> written inside a document is escaped, so a document cannot close the block early.
  • Every system prompt states that evidence is data and must not be followed as instructions.
  • The agent has no tools: no shell, no web access, no code execution. Its only actions are fixed graph steps.
  • The test suite includes an adversarial PDF that demands the model reply "PWNED", cite a fake source and reveal its prompt. Tests assert the structural defences and that the fake citation is rejected. A live test against the real model is included and runs on demand.
  • Secrets live only in .env, which is excluded from version control. The PDF endpoint validates the document ID format, which also blocks path traversal.

Each question is answered independently. The API is stateless by design for the MVP, which the guide flagged as a decision to make early; follow-up questions that refer to earlier answers are out of scope.

The Streamlit interface uses a dark, minimal visual language built around one cyan signal colour. It shows each agent step live with elapsed time, renders citations as chips that link to source cards, opens the original PDF at the cited page beside the answer, keeps a session history, and links each answer to its LangSmith trace.

10Observability

LangSmith tracing is optional and off by default. When enabled, each question appears as one run named "ResearchPilot agent", tagged with the model and retrieval settings. Each graph step is a child span, and every model call is recorded under the step that made it, with the full prompt, the JSON output, token counts and latency. Evaluation runs are tagged by system and question ID so a single variant can be filtered.

Tracing is set up so it cannot break the app: if the library fails, the client falls back to an untraced one. Because traces contain document passages, the report and the README both note that tracing should be turned off before querying personal documents.

Used in practiceThe first traced run exposed a real defect. The answer model had turned an internal instruction ("the search budget is exhausted") into one of its claims and cited sources for it. The prompt was reworded so the instruction is marked as not evidence, and the limitation note is now added by code instead.

Unit tests use a scripted fake LLM and a deterministic hashed-bag-of-words embedder, so the suite runs offline in under 20 seconds with no API key or model download. Test PDFs are generated by a small writer in the test fixtures. Linting uses Ruff. Dependency versions are pinned in requirements.lock.txt.

The LLM sits behind a thin interface that speaks the OpenAI-compatible protocol, so one setting switches between OpenAI, Ollama's cloud API and a local Ollama server. Every LLM output is parsed into a Pydantic schema, and malformed output raises a dedicated error that each step handles explicitly.

12How it was built

The project followed the milestone order in the design guide: foundations and tests first, then providers, then observability and the interface. The log below records decisions and problems as they happened.

Core systemMVP implemented and tested offline. Ingestion, retrieval, agent, citation checks, API, UI and evaluation harness, with 35 tests passing on the first run. A smoke test with the real embedding model, reranker and on-disk Qdrant confirmed persistence across restarts.
Cloud providerOllama cloud integrated, blocked by billing. The request reached Ollama and authenticated, then returned HTTP 402 because the account had no usage credits. The provider remains available as a setting.
Local modelSwitched to a local qwen3.5:4b. Requests to localhost timed out because Windows resolved it to IPv6 while Ollama listened on IPv4; using 127.0.0.1 fixed it. The model ran 100% on CPU with a 4,096-token context.
PerformanceDisabled hidden reasoning. A single call took 497 s and produced 824 output tokens for one sentence. Setting reasoning_effort to none cut that call to 28 s and 44 tokens. Context was reduced to 6 passages and 2 rounds to fit the window.
End to endFirst real agent run. The agent judged its first evidence insufficient, rewrote its queries toward the gap, and answered correctly on the second round. The model cited only through the claims list, which led to the claims-as-evidence rendering.
TracingLangSmith added and used to find a defect. The first trace showed the prompt-leak issue described in section 10, which was then fixed.
InterfaceRedesigned UI with a source viewer. PDFs are now stored on upload so the viewer can open the cited page. Deletion asks for confirmation.
DeliveryPublished to a private GitHub repository. A pre-commit check confirmed that no keys, PDFs or index files were included.

14Evaluation plan

The harness is complete and has been exercised in tests; it has not yet been run on a question set. It indexes a corpus into its own store, runs every system on the same questions, caches model outputs at temperature 0 so reruns give identical numbers, and reports means with bootstrap 95% confidence intervals.

Method

  • Gold set: 30 to 50 questions over 5 to 10 papers on one topic, mixing factual lookups, cross-paper comparisons, multi-evidence questions and questions whose answer is absent. Each answerable question records its supporting file and page. Questions are written and checked by hand so the answer key is not produced by the system under test.
  • Held-out split: about a third of the questions are marked as test and never used for tuning.
  • Metrics: recall@5 and context recall against gold pages, MRR, citation precision, correct abstention and false refusal (reported separately), latency, model calls, tokens and cost. An optional judge model, different from the answer model, scores faithfulness, relevance and correctness, and is spot-checked by hand on about 20 items.
  • Reporting rule: results are published as measured, including negative ones. If one-pass hybrid retrieval with reranking matches the agent at a fraction of the latency, that is a finding.

On this laptop the agent takes about 4 to 5 minutes per question and the one-pass systems 1 to 2 minutes, so the full comparison over 40 questions is an overnight run of roughly 10 to 12 hours. Cached outputs make every rerun free.

15Limitations

PrimaryNo comparative results yetWhether the agent beats simpler retrieval is unknown until the evaluation runs. No accuracy or improvement is claimed.
PrimarySlow on CPUAbout 4 to 5 minutes per question with a 4B model and no GPU. Usable for research, not for interactive demos.
PrimaryCitations are valid, not provenCode guarantees each citation points to a retrieved passage, not that the passage supports the claim. Claim-level verification is not built yet.
PrimaryThe evaluator can be wrongA small model decides sufficiency. It can stop early or waste a round; the limitation note covers the second case, not the first.
ModerateSmall context windowThe local model's 4,096-token window forced the context down to 6 passages and 2 rounds, which limits multi-document answers.
ModerateText PDFs onlyScanned PDFs are rejected with a clear message. Tables, equations and two-column layouts extract imperfectly with pypdf.
ModerateHeuristic cleaningHeader detection uses repetition, and cutting at "References" also removes any appendix after it. Both can be turned off.
ScopeIn-process keyword indexFine for hundreds of papers. A large corpus should move BM25 into Qdrant's native sparse vectors.
ScopeSingle user, no memoryNo authentication or multi-tenancy, and no follow-up questions. The embedded store also allows only one process at a time.
ScopeViewer depends on the browserJumping to the cited page relies on the browser's PDF reader honouring the page fragment, which Chrome and Edge do.
